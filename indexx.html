01

Utility-first: Tailwind vs CSS tradicional

En CSS tradicional inventas un nombre de clase y escribes sus reglas en otro archivo. En Tailwind compones el estilo directamente en el HTML/JSX combinando clases pequeñas y ya definidas — "utilidades" — una por cada propiedad.

CSS tradicional (como en v3)
/* App.css */
.tarjeta-contacto {
  background: #fff;
  border: 1px solid #d1d5db;
  border-radius: 10px;
  padding: 1rem;
  box-shadow: 0 1px 4px rgba(0,0,0,.08);
}

// Contacto.jsx
<div className="tarjeta-contacto">...</div>
Utility-first (Tailwind)
// Sin archivo CSS aparte:
<div className="bg-white border border-gray-200
  rounded-lg p-4 shadow-sm">
  ...
</div>

El resultado visual es idéntico — la diferencia es dónde vive el estilo. Con utilidades, el diseño queda a la vista junto a la estructura, y dejas de inventar nombres de clases para cada cosa nueva.

02

Instalación estable (v3.4) con Vite

Usamos específicamente Tailwind 3.4 — no la v4 — para mantener la configuración clásica con tailwind.config.js que se usa en el curso.

Terminal
  1. npm remove tailwindcss @tailwindcss/postcss
    Quitamos cualquier instalación previa o de la v4, para partir de cero.
  2. npm i -D tailwindcss@3.4.13 postcss@8 autoprefixer@10
    Instalamos la versión estable 3.4 junto con PostCSS y Autoprefixer, como dependencias de desarrollo.
  3. npx tailwindcss init -p
    Genera tailwind.config.js y postcss.config.js automáticamente (la bandera -p agrega también el de PostCSS).
03

Archivos de configuración

Cuatro archivos conectan Tailwind con el proyecto: le decimos dónde buscar clases, cómo procesarlas, y las importamos una sola vez.

tailwind.config.js
/** @type {import('tailwindcss').Config} */
export default {
  content: [
    "./index.html",
    "./src/**/*.{js,ts,jsx,tsx}",
  ],
  theme: {
    extend: {},
  },
  plugins: [],
};
content: [ ... ]
Le dice a Tailwind dónde buscar las clases que realmente usas, para generar solo el CSS necesario y no todo el framework completo.
theme.extend
Aquí se agregarían colores, tipografías o espaciados personalizados sin sobrescribir los valores por defecto de Tailwind.
postcss.config.js
export default {
  plugins: {
    tailwindcss: {},
    autoprefixer: {},
  },
};
tailwindcss: {}
PostCSS ejecuta Tailwind como un plugin: transforma tus clases utilitarias en CSS real durante el build.
autoprefixer: {}
Agrega automáticamente prefijos de navegador (-webkit-, etc.) cuando hacen falta, sin que tengas que escribirlos a mano.
src/index.css
@tailwind base;
@tailwind components;
@tailwind utilities;
src/main.jsx
import React from "react";
import ReactDOM from "react-dom/client";
import App from "./App";
import "./index.css"; // una sola vez, aquí

ReactDOM.createRoot(document.getElementById("root"))
  .render(<App />);

Las tres directivas @tailwind se importan una sola vez, en main.jsx — nunca en cada componente.

04

Rediseño de FormularioContacto.jsx

La lógica (estado, validación, onSubmit) no cambia respecto a la v3 — solo reemplazamos las clases CSS propias por utilidades de Tailwind.

src/components/FormularioContacto.jsx
  return (
    <form
      onSubmit={onSubmit}
      className="grid grid-cols-1 sm:grid-cols-2 gap-3
        bg-white border border-gray-200 rounded-lg
        shadow-sm p-5"
    >
      <div className="space-y-1">
        <label className="text-sm font-semibold text-gray-700">
          Nombre *
        </label>
        <input
          name="nombre" value={form.nombre} onChange={onChange}
          className="w-full border border-gray-300 rounded-md
            px-4 py-2 outline-none focus:ring-2
            focus:ring-purple-500"
        />
      </div>

      <button
        className="sm:col-span-2 bg-purple-600
          hover:bg-purple-700 text-white font-semibold
          rounded-lg py-2.5 transition"
      >
        Agregar contacto
      </button>
    </form>
  );
grid grid-cols-1 sm:grid-cols-2
Reemplaza el .form-contacto de v3: una columna en móvil, y a partir del breakpoint sm (640px), dos columnas — mismo comportamiento, sin escribir un @media.
rounded-lg shadow-sm border-gray-200
Tres utilidades = bordes redondeados + sombra suave + borde gris claro, el mismo look que antes daban las variables --radio, --shadow y --borde.
focus:ring-2 focus:ring-purple-500
Prefijo focus:: la utilidad solo aplica cuando el input tiene el foco — dibuja un anillo morado alrededor, dando feedback visual claro al escribir.
sm:col-span-2
El botón ocupa las dos columnas del grid a partir de sm, igual que hacía grid-column: 1 / -1 en el CSS de v3.
05

Rediseño de ContactoCard.jsx

Misma idea en la tarjeta: bordes, sombra y el botón "Eliminar" en rojo, ahora con bg-red-500 y hover:bg-red-600.

src/components/ContactoCard.jsx
  return (
    <article className="bg-white border border-gray-200
      rounded-lg shadow-sm p-4 flex items-center
      justify-between gap-4">
      <div>
        <h3 className="font-bold text-gray-800">{nombre}</h3>
        <p className="text-sm text-gray-600">📞 {telefono}</p>
        <p className="text-sm text-gray-600">✉️ {correo}</p>
      </div>
      <button
        onClick={() => onEliminar(correo)}
        className="bg-red-500 hover:bg-red-600 text-white
          text-xs font-semibold rounded-full px-4 py-2
          transition"
      >
        Eliminar
      </button>
    </article>
  );
flex items-center justify-between
La info del contacto queda a la izquierda y el botón "Eliminar" a la derecha, alineados verticalmente — tres utilidades de Flexbox en vez de CSS aparte.
bg-red-500 → hover:bg-red-600
Tailwind numera cada color en una escala de 50 a 900. red-500 es el rojo base; en hover: saltamos a red-600, un tono más oscuro, igual que hacía .btn-eliminar:hover en v3.
rounded-full
Aquí usamos un radio total (píldora) en vez de rounded-lg, para diferenciar visualmente el botón de eliminar del resto de la tarjeta.
